Optimization Options

Choose the constraints to respect while optimizing.

Scenario Levers

Run Model starts from the original imported Route Detail baseline, applies the selected levers, and can optimize/rebalance the network. Run Lite ReOp also starts from the original baseline, but only applies the requested direct changes and recalculates their effect on the existing routes — it does not reroute, resequence, condense routes, move surviving stops between routes, or enforce runtime balancing. If removals leave a route with no customer stops, that route remains in the scenario as an Empty Route. Removed orders remain visible as unassigned work. Full Model also treats matched truck Cube and Weight as hard capacity limits and deliberately tests whether light normal routes can be fully retired after scenario removals; Lite ReOp does not reroute or consolidate work. Partial Order Type scenarios use the same percentage/distance selection in both Lite ReOp and Full Model.

Optimization Mode

Improve Existing Routes uses the imported solution as the incumbent and keeps only beneficial changes. Build From Scratch clears customer assignments inside the model and rebuilds the remaining freight across the available imported route resources. All Scenario Levers apply in either mode. Build From Scratch defaults Route Lock and Sequence Lock to removed so the model can truly rebuild the network; you can intentionally turn either restriction back on afterward. If Route Run Time fields are blank, RouteER uses each resource's imported availability/run-time setting instead of applying one network-wide limit.

Order Types — Ignore

Choose whether the percentage applies to matching order lines, matching customer stops, or matching case volume. When the percentage is below 100%, RouteER prioritizes customers beyond the Distance Allowance first, starting with the farthest customer and working back toward the depot. Blank Distance Allowance still ranks farthest to nearest.

Minimum Case Count

Orders are combined by LocationKey and planned delivery day. If the remaining combined cases are below the entered minimum, those orders are moved to Unassigned.

Customer Windows

Open moves the EarlyDateTime earlier by the entered minutes. Close moves the LateDateTime later. Ignore All Customer Windows overrides those imported windows with 07:00–20:00.

Routing Locks

Assigned Customer Depot

Yes keeps each customer tied to the depot that serviced it in the original imported solution. If the optimizer moves the customer, it may only use another route assigned to that same depot. No allows the optimizer to use the most efficient feasible route across depots.

Optimization

Default 5 minutes. This is the maximum planned wait allowed at any individual customer stop during Full Model optimization. RouteER still penalizes every minute of wait and prefers zero wait whenever a feasible alternative exists; this allowance is not added to every stop.

Route Run Time

Hard limits for normal active modeled routes. Layover routes (route name contains Layover or a LocationKey beginning with L) are exempt from these network-wide Min/Max values and instead use layover-day limits: up to 10 active hours before each hotel anchor and up to 8 active hours after the final hotel anchor. An unused route with no planned stops is allowed.

Optional Delivery Expense Assumptions

If supplied, the After Action Report also estimates delivery expense as miles × cost/mile + route hours × cost/hour. Blank fields do not create a dollar estimate.
